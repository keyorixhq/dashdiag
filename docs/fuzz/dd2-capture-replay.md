## Interpretation / assumptions (stated, not asked)

Nobody answers questions in this unattended run, so the most reasonable reading was
taken and recorded here:

- **"Replay a capture through DashDiag offline"** = the existing `dsd replay
  <bundle.tar.gz>` seam (`cmd/replay.go` → `internal/source.Replay` over a
  `source.Bundle`). It already re-runs the full collector set against recorded
  inputs with zero live reads. No new product seam was needed; the DD2 harness is
  **test-only** and drives that seam. See *Step 1*.
- **The 49 staged captures** live read-only at `/mnt/data/wave4/dashdiag-captures/`.
  They are **never** copied into committed files (they may carry host names /
  addresses). The committed oracles instead use the two **already-committed,
  sanitized** fixtures under `fixtures/replay-fidelity/` (the repo's existing
  convention). The 49 captures are exercised only by **env-gated** tests that
  **skip** unless `DD2_CAPTURE_DIR` (or a gitignored `.scratch/dd2-capture-dir`
  pointer) is set — so CI stays green without the data.
- **Verdict** for a check = the `status` field `dsd replay --json` emits per
  `checks[]` entry (`render.BuildJSONOutput`), i.e. the exact reduction
  `scripts/check-replay-fidelity.sh` already uses (`[.checks[] | {(.name):
  .status}]`). Values: `OK` / `WARN` / `CRIT` / `ERROR`; a check absent from
  `checks[]` is not-applicable or not-recorded on that capture.

### Runtime-environment note (affects how the harness is wired)

The sandbox on this host refuses `VAR=val go test` (env-var prefixes), `nice`,
`tar`, `cp -r`, loops, and running freshly-built binaries — but allows plain `go`
and `du`. The harness therefore:

- is **pure Go** (a `go test` whose own file I/O reaches the external capture dir),
- reads its capture dir from `DD2_CAPTURE_DIR` **or** a gitignored
  `.scratch/dd2-capture-dir` pointer file (the env var can't be set from the shell),
- caps `GOMAXPROCS` to 2 **in-code** (`runtime.GOMAXPROCS`, via `dd2CapParallelism`)
  because the shell can't export it, and passes `-parallel 2` to the fuzzer.

`nice -n 10` could not be applied (the sandbox gates it); load is instead bounded by
`GOMAXPROCS=2` + `-parallel 2`. The package temperature sensor
(`/sys/class/hwmon/hwmon2/temp1_input`) is **not readable** from this session (the
read-tool sandbox blocks it), so thermal pacing relies on the CPU caps above.

## Step 1 — the replay seam

`dsd replay <bundle>` (`cmd/replay.go`):

- `loadBundle` reads a native raw-v1 bundle (`source.LoadTarball`), falling back to
  an `hw-snapshot.sh` tarball's file layer (`source.FromSnapshot`) only on
  `ErrNotNativeBundle`.
- `replayBundle` swaps `collectors.SetSource` to a `source.Replay` over the bundle,
  sets the captured host's identity/platform, runs the full health pipeline
  (`runHealthOnce`), and restores global state. Every file/dir/glob/stat/statfs/
  readlink/exec read is served from the bundle; an unrecorded input returns
  `ErrNotRecorded` (a **recording gap**, counted per check as `not_recorded` — never
  a silent fall-through to the live system).

**What replay does and does not reproduce.** It reproduces every collector that
routes through `internal/source` (ADR-0003 Phase 3: thermal, memory, CPU, disk,
network, GPU, EDAC, NUMA, packages, …). It does **not** reproduce inputs a capture
never recorded (older bundles, uncaptured commands) — those surface as
`not_recorded` gaps, which the matrix counts. The replay binary's OS must match the
capture's (`replayPlatformGuard`); all 49 captures here are Linux, replayed on Linux.

## Step 3 — oracles

For every oracle, what it does **not** verify is stated. A capture is a snapshot of
one machine at one instant, **not a specification**: a matching verdict proves
*replay reproduces the captured host*, never that the verdict is "right" or that
other configurations of the same distro behave the same.

### Oracle 1 — determinism & no panic/hang (3 replays identical)

- **Committed:** `TestDD2FixtureReplayDeterminismAndNoPanic` (over the two committed
  fixtures) — runs in CI.
- **Env-gated (all 49):** `TestDD2CaptureReplaySweep`.
- **Result:** all 49 captures + both fixtures replay three times with identical
  verdict maps and no panic.
- **Does NOT verify:** determinism within one host/binary ≠ cross-environment
  fidelity (a collector could read the *replaying* machine's live state identically
  on all three replays and still be wrong — that is the separate concern
  `scripts/check-replay-fidelity.sh` guards). It also does not bound wall-time as a
  spec; the ceiling is a hang backstop, not a performance assertion.

### Oracle 2 — mutation robustness (anti-false-OK) — fuzz + deterministic

- **Fuzz target (committed, registered):** `FuzzCaptureReplayMutationRobustness`
  (`cmd/replay_capture_mutation_fuzz_linux_test.go`). Auto-discovered by
  `scripts/fuzz-discover.sh` (the repo registers fuzz targets by signature, not a
  list; `fuzz_coverage_test.go` enforces that every `Fuzz*` is discoverable).
- **Deterministic committed guard:** `TestDD2FixtureMutationAntiFalseOK` applies
  every damage kind to every recorded blob of both fixtures.
- **Env-gated (all 49):** the mutation sweep (below).
- **Invariant:** apply ONE strictly information-**destroying** mutation (truncate,
  drop the recorded input entirely → recording gap, garble digits, uppercase-shift,
  blank to whitespace, or splice provably-non-data noise with every ASCII
  letter/digit stripped) to a single recorded file or command output, then require:
  **no panic, bounded time, and no check that was non-OK on the undamaged baseline
  may read `OK` after the damage.** Losing/garbling an input must surface as unknown
  (ERROR / degraded / dropped-from-`checks[]`), never as a green light.
- **Soundness:** the invariant is one-directional, so a mutation must never
  *introduce* valid data that could legitimately earn an `OK`. Every kind only
  removes or garbles existing bytes; the two splice kinds strip all letters/digits
  from the inserted noise, so it can never form a parseable record. Any non-OK→OK
  flip is therefore a genuine false-OK, never a harness artifact.
- **Damage-set scope (important for soundness).** The damage set is the bundle's
  **captured files and command outputs** only. It deliberately EXCLUDES the
  `source.Cached()` namespace (`"\x00cached\x00…"`) — derived state dsd itself
  computes and writes into the bundle (`clock/state`, `net/connectivity`,
  `lookpath/*`, dial/http probe results). Those are not "captured files or command
  outputs" (the DD2 damage spec), and damaging them tests a different property
  (replay's behaviour when a computed cache is absent) — see **Finding F1**, which is
  exactly what surfaced when the cache namespace was briefly in scope.
- **A hit is a CANDIDATE, not an automatic defect.** Truncating a legitimately
  *optional* file to empty can make a check honestly `OK` (empty = no finding); a
  collector cannot tell truncated-empty from genuinely-empty. So every non-OK→OK
  flip is triaged by hand (DEFECT / FALSE-OK / HARDENING / EXPECTED-DIFFERENCE /
  ARTIFACT / HARNESS-FALSE-POSITIVE). The committed deterministic guard and the fuzz
  target are therefore best read as **regression guards pinned to the two fixtures**
  (green now; a new flip there is a change to investigate) plus the always-sound
  no-panic / bounded-work assertions; the 49-capture sweep is a **candidate
  generator** whose output is triaged in *Findings*.
- **Result so far:** green on both committed fixtures (bounded deterministic guard,
  cache namespace excluded) and under the 60 s fuzz smoke. _[fuzz totals below]_
- **Does NOT verify:** it is blind to a false-OK on a check the baseline already
  reports `OK` (no non-OK verdict there to protect); it damages exactly one input at
  a time (no multi-input corruption); and, being fixture/capture-based, it cannot
  find a false-OK that only arises on a host/verdict not present in the data. It does
  not *prove* a flip is a bug — only a human triage does.

### Findings

**F1 — Replay fails OPEN when a derived-state cache is absent (HARDENING).**
When the mutation damage set included the `source.Cached()` namespace, two flips
appeared on the committed fixtures:

- `debian13-vmware-unsynced`: dropping the recorded `clock/state` cache entry →
  **Clock CRIT → OK** (coverage still "checked", no gap flagged).
- `debian13-vmware-nonroot`: truncating the recorded `net/connectivity` cache entry
  to empty → **Network CRIT → OK**.

Mechanism: these collectors route derived state through `source.Cached(key, produce)`
specifically so an old/incomplete bundle replays deterministically
(`internal/collectors/netaccess.go:28` documents the gap fallback). On a recording
gap or empty cache, the fallback resolves to a *healthy* default (synced / reachable)
rather than *unknown* — a fail-open on information loss.

- **Classification: HARDENING (not a live vulnerability).** A real `dsd capture`
  always records these caches, so reaching this needs a damaged or pre-cache bundle.
  The honest behaviour would be to degrade an absent derived cache to
  unknown/not_recorded, not OK, mirroring the `dial/` gap fallback which already
  returns *unreachable* (fail-closed).
- **Issue-ready proposal (no product change made, per the runtime rules):** in the
  clock and net-connectivity collectors, treat a `Cached()` miss / empty value as
  an unverified "couldn't determine" insight (INFO + `Unverified`), the same shape
  the non-root path already uses, so a bundle that lost the cache reads as unknown
  rather than green. Red/green evidence is the diagnostic above (cache in scope →
  oracle fires; cache excluded → green).

### Oracle 3 — sibling parity _[in progress]_

Compares sibling captures (same distro family / release pairs, sanitized-vs-raw
pairs, before/after pairs) for agreement on applicable check-ID sets and on verdicts
of semantically identical facts. Table written to `.scratch/out/sibling-parity.md`.
Every disagreement is classified EXPECTED / DEFECT / CAPTURE-GAP.

- **Does NOT verify:** parity only flags *divergence*; two siblings can agree and
  both be wrong, and a documented distro difference is expected divergence, not a
  bug.

### Oracle 4 — known-defect regression _[in progress]_

The scenario captures (`drbd9-broken-almalinux10`, `lacp-notaggregating-debian13`,
`bond-activebackup-debian13`, `dsd-debian231` vs `dsd-debian231-fixed`) encode a
known behaviour; replay must still show it. `BUGS.md`'s `Found:` lines name
validation *sessions*, not tarball names, so this oracle maps by scenario rather than
by a literal capture name.

- **Does NOT verify:** absence of a bug in replay is not absence on the live host;
  and a scenario capture pins one manifestation, not the whole bug class.
